04 / REFACTORING

舊系統到 Spring Data JPA，
六項結構改進

把字串拼接與肥大的 DAO，改成可驗證、可維護的分層。每一格都看得到舊寫法、新寫法，以及為什麼要改。

3 項改進直接消除 SQL 注入風險（1、2、6）
1000+ 行CatchDAO 拆成三層職責
6 個Projection / DTO 取代整個 Entity
1

分頁現代化

防 SQL 注入
舊
"order by ... limit " + iFrom + "," + iRecLimit

字串拼接，易被 SQL 注入。

新
Pageable pageable + Page<T> findXXX(...)

由框架處理分頁與總筆數，參數不再拼進 SQL。

2

SQL 注入防護

資安
舊
_sbCond.append(" and tc_psa01 in ("+_sbCond.toString()+")")

條件直接拼接，易被 SQL 注入。

新

ObaRepositoryCustom 用 ALLOWED_SORT_COLUMNS 白名單限制排序欄位。

CatchRepositoryImpl 用 NamedParameterJdbcTemplate 綁定參數。

3

複雜查詢分離

可維護性
CatchDAO全部塞在一起
超過 1000 行
→
CatchRepository簡單查詢，交給框架
CatchRepositoryCustom介面，定義複雜查詢
CatchRepositoryImpl複雜查詢的實作

同樣的模式也套用在 LpkFileRepository → LpkFileRepositoryCustom → LpkFileRepositoryCustomImpl。

4

Projection / DTO

效能與安全
舊
Transformers.aliasToBean(Entity.class)

一律用整個 Entity 承接查詢結果。

新

只取需要的欄位，用專用的資料載體：

TargetPsaDtoCampaignRedeemProjectionContractProjectionMemberDataProjectionCouponDtoLogDbProjection
減少連鎖影響Entity 改欄位不波及查詢
不再靜默失敗欄位對不上會明確出錯
防敏感外洩只回傳該給的欄位
效能提升少讀不需要的資料
避免 N+1 與延遲載入副作用：若 Entity 有 @OneToMany 關聯（例如 LPJ_FILE 關聯 LSM_FILE），用 Entity 查詢時，只要程式不小心碰到關聯屬性，Hibernate 就會額外發出 SQL（N+1 問題）。Projection 是純資料載體，不會觸發任何延遲載入。
5

批量 / 條件式更新

效能
舊

迴圈逐筆 executeUpdate()，例如 BudgetDAO.saveBudget。

新

@Modifying 搭配 CASE WHEN 一次更新，例如 ItRequestRepository.updateRejectStatus：用單一 SQL 完成 3 種狀態的 reject。

6

動態排序

防 SQL 注入
舊
"order by t1."+sSidx+" "+sSord

直接拼接，風險高，易被 SQL 注入。

新
CASE WHEN :sidx = 'xxx' THEN t1.xxx END

搭配參數綁定，例如 AssetInventoryRepository.findInventoryOrderByDept。
